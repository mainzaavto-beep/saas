## 1. Backfill за 75 дней при онбординге нового клиента

**Проблема:** при подключении нового кабинета данные вообще не собирались — три компаунд-бага:
1. Креды лежали в `auth.shops.api_creds_enc`, а воркер читал из `auth.cabinets` → пусто.
2. `marketplaces = '{}'` (пустой массив) — воркер пропускал кабинет.
3. `status = 'provisioning'` навсегда — ежедневный сбор только `active`.

**Решение:**
- `app/api/onboarding/start/route.js` — создаёт кабинет сразу `active` + заполненный `marketplaces[]` + onboarding-job (`date_from=сегодня−75`) в той же транзакции.
- `app/onboarding/page.js` — передаёт `marketplaces` (unique из shops).
- `worker/orchestrator.py` — переписан: креды из `auth.shops` (per-МП, per-юрлицо), legacy-fallback на кабинетные creds (для cabinet #1). Режим `--drain-queue` — берёт queued onboarding-jobs (`FOR UPDATE SKIP LOCKED`), гоняет сборщики за 75 дней, паузы между job'ами.
- Новый таймер `saas-backfill` (4×/день: 07:00, 10:30, 14:00, 19:00) + `worker/run_saas_backfill.sh`.
- Прокси НЕ нужен (сервер в РФ). Закладывать при 50+ клиентах.

## 4. Единый источник себестоимости (главное архитектурное решение)

**Проблема:** себестоимость в 2 таблицах — `wb_cogs`/`ozon_cogs` (283 SKU база) и
`cost_overrides` (4 SKU override). Канон: override приоритетнее cogs. Но 8 из 11 роутов
читали только cogs → расхождения.

**Решение:** единый источник = `tenant.cost_overrides`. Миграция `013_unify_cogs.sql`:
- Все SKU из cogs перенесены в cost_overrides (`effective_from='2020-01-01'`, покрывает историю).
- История `order_costs` (1716 WB + 376 Ozon строк) пересчитана (cost+profit).
- `wb_cogs`/`ozon_cogs` НЕ дропнуты (архив), но убраны из всех SELECT'ов.

**Код переведён (11 роутов + 3 либы + 2 сборщика):** orders, overview, products-summary,
items, pnl, detail, unit/all, mp-stock + mpStockValue.js, wbMetrics.js, finItems.js (хелперы
WB_COST_JOIN/OZON_COST_JOIN) + wb_order_costs.py, ozon_order_costs.py. Паттерн — LATERAL JOIN:
```sql
LEFT JOIN LATERAL (
  SELECT cost FROM tenant.cost_overrides
  WHERE nm_id = X.nm_id AND platform = 'wb'
    AND effective_from <= COALESCE(substr(date,1,10)::date, current_date)
  ORDER BY effective_from DESC LIMIT 1
) co ON true
```
Бэкап для отката: `/opt/agentsDB/backups/cogs_unify_20260714_200601.sql`.

## 5. Миграционные баги портов страниц (3 класса, массово почищены)

Страницы портированы из single-tenant data-presenter (где БД была **синхронным SQLite**).
SaaS-адаптер **асинхронный** + мультитенантный → каскад несовместимостей:

- **D1 (cabinetId):** компонент не принимает `{ cabinetId }` как пропс → fetch на `/api/cabinets/undefined/...`.
- **D2 (URL без cabinet):** `fetch('/api/purchases')` вместо `/api/cabinets/${cabinetId}/purchases`.
- **D3 (двойные кавычки):** `fetch("/api/.../${cabinetId}/...")` — интерполяция в двойных кавычках = литеральный текст.
- **D4 (async без await):** `.all().map()` / вызов async-функции без await (эталон был синхронным SQLite).
- **D5 (SQLite-функции):** `datetime(dt, '+3 hours')`, `strftime` — не существуют в PG.
- **D6 (фасеты/ответ API):** фронт ждёт `totals.by_category`, API отдаёт `facets.categories` → undefined.map().

**Починенные страницы:** OpexPage (сопутств. расходы), PurchasesPage (закупки), SelfBuyoutsPage,
BalancePage, DdsPage, PlanPage, MovePage, CatalogPage, MpStockPage, FfStockPage, BriefingPage,
AlertsPage, CalendarPage, PurchasePlanPage, TimingPage (заказы по времени).

**Скрининг при новых портах:** `grep -rn 'fetch("[^"]*\${' app/cabinets/` должно быть пусто.
