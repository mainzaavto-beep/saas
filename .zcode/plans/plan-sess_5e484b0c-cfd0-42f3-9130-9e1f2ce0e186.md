## Фаза 1 — Next.js SAAS под systemd (20 мин)
Создать `/etc/systemd/system/saas-web.service`:
- `Type=simple`, `User=root`, `WorkingDirectory=/opt/agents/saas`
- `ExecStart=/usr/bin/npm run start` (это `next start -p 3200`)
- `Restart=on-failure`, `RestartSec=5`
- `After=network.target postgresql.service` (поднимать после сети и БД)
- `EnvironmentFile=/opt/agents/saas/.env.local` (пробросить SAAS_* переменные)

Порядок переноса **без простоя**:
1. `systemctl daemon-reload && systemctl enable saas-web`
2. Остановить старый процесс (PID 113826) → `systemctl start saas-web`
3. Проверить: `systemctl status saas-web`, `curl -I https://sysell.ru`
4. Caddy не трогаем — он уже проксирует `:3200`

**Результат:** сайт поднимается после ребута, перезапускается при падении.

## Фаза 2 — Воркер под systemd timer (15 мин)
Создать два файла:
- `/etc/systemd/system/saas-worker.service` (`Type=oneshot`, `ExecStart=/opt/agents/saas/worker/run_saas_worker.sh`) — разовый прогон (воркер сам выходит)
- `/etc/systemd/system/saas-worker.timer` (`OnCalendar=*-*-* 04:00:00`, `Persistent=true`) — каждая ночь в 04:00

Проверка:
1. `systemctl start saas-worker` (разовый ручной прогон сейчас)
2. Смотреть лог `/opt/agentsDB/logs/saas_worker.log` — воркер должен собрать данные с активных кабинетов
3. Если падает — разобраться почему (env-файлы `/etc/saas-worker.env` + `/etc/collectors.env` существуют, venv тоже есть)
4. `systemctl enable saas-worker.timer` → запуск по расписанию

**Результат:** данные с WB/Ozon снова тянутся автоматически каждую ночь.

## Фаза 3 — Бэкапы PostgreSQL (15 мин)
Создать `/opt/agentsDB/backup_saas.sh`:
```bash
# pg_dump базы saas → gz с датой, удаление старше 14 дней
ts=$(date +%Y%m%d_%H%M%S)
pg_dump -h localhost -U saas_app saas | gzip > /opt/agentsDB/backups/saas_${ts}.sql.gz
find /opt/agentsDB/backups/ -name 'saas_*.sql.gz' -mtime +14 -delete
```
(пароль возьму из `.pgpass` или `.env.local` через PGPASSWORD)

systemd: `saas-backup.service` (oneshot) + `saas-backup.timer` (`OnCalendar=*-*-* 03:00:00` — до воркера).

Проверка: первый бэкап руками, убедиться что файл > 0 и внутри — корректный дамп.

**Результат:** база бэкапится каждую ночь, хранится 14 дней. Потеря базы = потеря бизнеса — этого больше не случится.
