# Дефолтные окна «по вчера» — дизайн

Дата: 2026-08-25. Статус: согласовано с владельцем (чат) — «везде, где дефолт „по сегодня"».

## Зачем

Сегодняшний день финансово всегда недособран: расходы (логистика, реклама, сборы) начисляются раньше выручки, и текущая дата в дефолтном окне «тянет в минус» прибыль на главной и других экранах. Владелец: «нужно по предыдущий день делать».

## Правило

Дефолтный период каждого роута/экрана, который сейчас заканчивается СЕГОДНЯ (`new Date().toISOString().slice(0,10)` при отсутствии query-параметров), заканчивается ВЧЕРА; длина окна сохраняется (30 дней остаются 30 днями: `from = to − (N−1)`). Явно выбранный пользователем период (query-параметры, пикеры) НЕ ограничивается — «сегодня» можно выбрать руками везде.

## Реализация

1. **Хелпер** `lib/period.js`:
   ```js
   // Дефолтное окно панели: последние N дней ПО ВЧЕРА. Сегодня всегда
   // финансово недособрано (расходы приходят раньше выручки) — текущая
   // дата в дефолте занижает прибыль (решение владельца 2026-08-25).
   // Датировка — UTC-строками, как во всех роутах (договорённость не меняем).
   export function defaultPeriod(days = 30) {
     const to = new Date(Date.now() - 864e5).toISOString().slice(0, 10);
     const from = new Date(Date.now() - days * 864e5).toISOString().slice(0, 10);
     return { from, to };
   }
   ```
   (`days*864e5`, потому что to уже −1 день: окно [to−(days−1), to] = [сегодня−days, вчера].)
2. **Аудит и перевод**: grep всех роутов app/api и страниц на дефолт «по сегодня» — известно минимум `overview/route.js:125-126`; сводка/РНП/detail/pnl/abc и пр. — по факту аудита. Каждое место: дефолт → `defaultPeriod(N)` с прежним N. Явные параметры — без изменений.
3. **Клиент**: якоря пикеров, подгоняемые под серверный дефолт (OverviewClient:118-131 и аналоги) — сверить, что подгонка работает от `period.from/to` ответа (тогда правок не надо); где дефолт дублируется на клиенте — перевести на тот же расчёт.
4. **Не трогаем**: дефолты «от MAX(order_dt)» (витрина заказов — окно от последних данных, не от календаря); фиксированные окна чек-скриптов; worker.
5. **Сторожа**: check-profit-canon (фиксированное окно) и profit-snapshot --verify (явные периоды) — прогнать, ALL PASS; lossMakers Обзора автоматически едет за окном Обзора (30 дней по вчера) — состав может сдвинуться на день, это ожидаемо и в отчёте фиксируется.

## Приёмка

- Обзор без параметров отдаёт `period.to` = вчера; подпись периода на экране совпадает.
- Ручной выбор «по сегодня» работает во всех пикерах.
- Сторожа ALL PASS.
