# Рестайл панели, этап 3 «текст на акценте» — дизайн

Дата: 2026-08-23. Статус: владелец сказал «давай этап 3» — продолжение
принятых этапов 1-2, новых дизайн-решений нет (правило `--accentInk`
утверждено этапом 2, здесь оно доводится до всех инлайн-мест).

## Зачем

Финальное ревью этапа 2 нашло два «семейства» инлайн-текста на акцентных
кнопках/чипах мимо правила accentInk: ~27 мест `color:"#fff"` (в тёмной
теме 3.13:1 — ниже AA) и ~50 мест `color:"#0A1A1C"` (в светлой ~3.2:1).
Плюс хвосты: «чужая» палитра LIFECYCLE_COLOR в закупках, декоративные
hex-серии графиков детальной страницы, два устаревших комментария из
плана алертов, fallback-значения `var(--neg, #ff6b6b)` со старой палитрой.

## Компоненты

1. **Свип «текст на акценте»**: оба семейства → `var(--accentInk)` —
   ТОЛЬКО там, где фон элемента действительно акцентный
   (`C.accent`/`var(--accent)`/`C.blue`); места с фоном neg/pink/тепловых
   карт/disabled-состояний НЕ трогать (список исключений ревью: OpexPage
   на C.neg, InventoryPage на C.pink, TimingPage heatmap). Auth-страницы,
   где элемент по сути кнопка `.btn`, — можно переводить на класс.
2. **Палитры-сироты**: LIFECYCLE_COLOR (PurchasesPage) и декоративные
   hex-серии DetailPage (#7DD3FC, #86EFAC, #A78BFA…) → токены/`SERIES`
   (расширить SERIES при нехватке позиций производными через color-mix);
   fallback-хвосты `var(--x, #старый)` → чистые `var(--x)`.
3. **Комментарии-хвосты алертов**: lib/opsAlerts.js:62 («±30 мин» →
   асимметричное окно), saas-worker.service («14 сборщиков» → 17).

## Что НЕ входит

HealthPage (сознательно «терминальный» вид — решение задокументировано);
P&L eyebrow-группы (нужны поля API — отдельное решение владельца);
любые изменения данных/роутов/текстов.

## Приёмка

Как этапы 1-2: деплой → владелец смотрит страницы с кнопками/чипами
(Обзор, P&L, Заказы, Закупки, Детальная) в обеих темах. Сторожа ALL PASS.
Grep-критерий: `color:"#fff"`/`#0A1A1C` рядом с акцентным фоном — ноль.
