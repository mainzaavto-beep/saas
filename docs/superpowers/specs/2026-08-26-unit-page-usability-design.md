# Юнит-экономика: ширина, читаемость, персист прикидок — дизайн

Дата: 2026-08-26. Статус: согласовано с владельцем (чат): боли — «строки факта/прикидки сливаются, непонятно что редактируемо», «прикидки теряются при обновлении», «расширить во весь экран»; сохранение — в БД с автосейвом.

## Решения

1. **Ширина**: `UnitPage.jsx:175` `maxWidth: 1640` → убрать (100% с текущими паддингами). Таблица уже имеет свой minWidth/скролл.
2. **Читаемость** (только токены C.*/soft, паттерн «островов» рестайла):
   - строка ПРИКИДКА: левая акцент-полоса (`boxShadow: inset 3px 0 0 C.accent` или borderLeft) + фон `soft("accent", 6-8)`; строка ФАКТ — как сейчас;
   - редактируемые входы — input с рамкой `1px solid C.line`, фокус `C.accent`; вычисляемые значения — текст без рамки;
   - вход, отличающийся от фактического значения, — жирный + точка-маркер `C.accent`; у строки кнопка «⟲ к факту» (сбросить входы прикидки к фактическим);
   - легенда над таблицей: «Серая строка — факт из БД. Синяя — прикидка: меняйте поля с рамкой, прибыль пересчитается. Сохраняется автоматически.»
3. **Персист**:
   - миграция `db/migrations/046_unit_whatif.sql` (идемпотентная, BEGIN/COMMIT, конвенция 041-045): `tenant.unit_whatif (cabinet_id BIGINT NOT NULL, platform TEXT NOT NULL CHECK (platform IN ('wb','ozon')), item_id BIGINT NOT NULL, inputs JSONB NOT NULL, updated_at TIMESTAMPTZ NOT NULL DEFAULT now(), PRIMARY KEY (cabinet_id, platform, item_id))` + RLS-политика tenant_iso как у соседних tenant-таблиц + **политика `panel_local_ro_cab1`** (правило владельца для новых tenant-таблиц — образец с существующей таблицы);
   - API: чтение прикидок — в существующем `unit/all` (или `unit/inputs`) добавить whatif-блок ответа; запись — `POST /api/cabinets/[id]/unit/whatif` (upsert inputs по товару; `DELETE`-семантика — POST с inputs:null или отдельный метод, по конвенции соседних роутов); запись в tenant — через штатный db-механизм роутов (как «↧ в факт» уже пишет);
   - клиент: автосейв с дебаунсом ~1000 мс, индикатор «Сохранено/Сохранение…» ненавязчиво у легенды; кнопка удаления прикидки товара (очищает строку к факту и удаляет запись);
   - сид: при загрузке страницы прикидки из БД накладываются на строки.
4. **Не в скоупе**: формулы `calcWB`/`calcOzon` (жалоб на числа нет); «↧ в факт» как есть; мобильная вёрстка.

## Приёмка

- Ширина: страница занимает весь вьюпорт (нет центрирующего ограничителя).
- Ввести прикидку → обновить страницу → значения на месте (из БД, sql-подтверждение); «⟲ к факту» очищает и удаляет запись; индикатор работает.
- Прибыль прикидки пересчитывается как раньше (calc* не тронуты — диффом).
- Сторожа ALL PASS (страница не входит в канон-цепочку — не должны шевельнуться).
