# Калькулятор себестоимости с доставкой из Китая — дизайн (22.10.2026)

## Зачем
Быстрая прикидка себестоимости 1 шт товара из Китая до фулфилмента: владелец вводит вес, цену в
юанях, ставку карго, логистику до ФФ, курсы и количество — панель сразу считает и сохраняет расчёт
строкой, к которой можно вернуться, поправить или скопировать под другой товар.

Это прикидка, не учёт: с «Закупками» (`computeExcel`, предоплата, курс оплаты) не связана и их
формулы не трогает. В P&L/юнитку/себестоимость (`cost_overrides`) ничего не пишет.

## Формула (`lib/costCalc.js`, чистая функция `calcCost(input)`)
Ввод (решения владельца 22.10): вес — **за 1 шт**, ставка карго — **$/кг**, логистика карго→ФФ —
**₽ за партию**, доставка по Китаю — **¥ за партию**.

| Поле | Ед. |
|---|---|
| `name` — товар | текст |
| `qty` — количество | шт |
| `weight_kg` — вес 1 шт | кг |
| `price_cny` — цена 1 шт | ¥ |
| `china_delivery_cny` — доставка по Китаю | ¥ за партию |
| `cargo_usd_per_kg` — ставка карго | $/кг |
| `ff_logistics_rub` — логистика карго → ФФ | ₽ за партию |
| `rate_cny` — курс ¥→₽ | ₽ |
| `rate_usd` — курс $→₽ | ₽ |
| `note` — комментарий | текст |

- `goodsRub = price_cny × qty × rate_cny`
- `chinaRub = china_delivery_cny × rate_cny`
- `weightTotal = weight_kg × qty`
- `cargoRub = weightTotal × cargo_usd_per_kg × rate_usd`
- `ffRub = ff_logistics_rub`
- `totalRub = goodsRub + chinaRub + cargoRub + ffRub`
- `unitRub = totalRub / qty` (при `qty ≤ 0` → `null`)
- по каждой статье: `perUnit = статья / qty`, `share = статья / totalRub` (при `totalRub = 0` → `null`)

Пустое/нечисловое поле = 0 (кроме `qty`: пусто → результат за штуку `null`). Округление — только
при показе (деньги до копеек), функция возвращает точные числа.

## Хранение
Миграция `074_cost_calcs.sql`: `tenant.cost_calcs` — `cabinet_id, id BIGSERIAL, name, qty,
weight_kg, price_cny, china_delivery_cny, cargo_usd_per_kg, ff_logistics_rub, rate_cny, rate_usd,
note, created_by (user_id), created_at, updated_at`; PK `(cabinet_id, id)`. RLS как у
`order_matrix_hidden` (политики `tenant_iso_*`, `panel_local_ro_cab1`, гранты `saas_app`). Храним
только ввод — результат всегда пересчитывается `calcCost`, расходиться не с чем.

## API `/api/cabinets/[id]/cost-calc`
- GET (любая роль): `{ items: [ввод + результат calcCost], defaults }`, сортировка по
  `updated_at DESC`; `defaults` — курсы/ставки/логистика из последнего сохранённого расчёта.
- POST (`requireRole: 'manager'`): `{action:"save", id?, ...ввод}` — без `id` создаёт, с `id`
  обновляет (`updated_at = now()`); `{action:"delete", id}`. Валидация: `name` непустой (≤200),
  числа конечные и ≥ 0. `created_by` — из сессии.

## Страница `/cost-calc`
Меню «Закупки» → «Калькулятор себестоимости» (`lib/cabinetNav.js`, после «Закупок»).
- Форма ввода; результат пересчитывается на лету: себестоимость 1 шт крупно, итого партии, вес
  партии, таблица статей (₽ партия / ₽ на шт / доля %).
- Кнопки: «Сохранить» (новый или обновить открытый), «Сохранить как новый» (копия — для другого
  товара), «Новый расчёт» (очистить товар/вес/цену/кол-во, курсы и ставки — из `defaults`).
- Ниже — сохранённые расчёты: название, дата, кол-во, ₽/шт, итого, поиск по названию; клик —
  загрузить в форму; ✕ — удалить (с подтверждением). Viewer видит, кнопки записи скрыты.
