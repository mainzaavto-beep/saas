## Зачем

Этап 1 сменил фундамент (токены/типографика/общие классы), но финальное
ревью нашло «острова старой палитры» — страницы с захардкоженными цветами

### 2. Решение «текст на акценте» + контраст-долги

Одно правило на обе темы, применяется к `.btn`, `.topnav-link.active`,
`.avatar-btn` и активным чипам страниц:
- светлая тема: белый текст на `--accent #2E5CE6` (контраст достаточный,
  точное значение фиксирует план по WCAG-формуле);
- тёмная тема: тёмный текст `#131417` на `--accent #6B8DF2` (сейчас белый
  даёт 3.13:1 — ниже AA; тёмный на светлом акценте — заведомо выше).
Новый токен `--accentInk` (цвет текста на акценте, свой на тему) — чтобы
правило жило в одном месте.
Контраст-долги закрываются правкой значений: светлый `--warn` темнее
(≈#9C6414, до ≥4.5:1 на белом), светлый `--pink` темнее до ≥4.5:1 на
15%-подложке бейджа (или % подложки выше) — точные значения подбирает
план с WCAG-проверкой в шагах.

### 3. Композиция трёх главных страниц (язык макета)

Только JSX/стили, данные и роуты не трогаются:
- **Обзор**: первый KPI (прибыль периода) — primary-плитка крупно
  (~30px) с мини-спарклайном (SVG по уже имеющемуся дневному ряду ответа
  роута; если ряда в ответе нет — спарклайн опускается, НЕ добавляем полей
  в API), остальные плитки вторым рядом тише.
- **Сводка**: KPI-ряд в том же порядке и стиле, что на одобренном макете
  (Прибыль primary → Выручка → Реклама → Продано → Выкуп; ДРР и
  Кабинетные расходы остаются, вторым рядом); числовые колонки таблицы —
  выравнивание вправо (сейчас местами левое).
- **P&L**: группы строк с подзаголовками-eyebrow (11px uppercase muted),
  итоговые строки выделены (полужирный + верхняя граница), числа вправо.
Существующие тултипы/тексты методологии сохраняются дословно.

### 4. Dataviz-палитра

Серии графиков — от токенов: базовый набор
`[var(--accent), var(--pos), var(--warn), var(--pink), var(--accent2)]`
одним модулем (`lib/palette.js` — экспорт `SERIES`), на него переводятся
PIE_PALETTE в OpexPage (#00E5FF и пр.) и жёлтые серии DetailPage
(#FBBF24). `lib/theme.js` (мёртвая третья палитра) — удалить,
предварительно подтвердив grep-ом ноль импортов.

## Приёмка

Как в этапе 1: деплой по протоколу → владелец смотрит живую панель (обе
темы; отдельно — Отзывы, Обзор, Сводку, P&L) → «ок»/«откати»/«поправь».
Постраничные скриншоты не требуются; откат = git revert + build. Сторожа
после деплоя: check-profit-canon (1, 1008), profit-snapshot --verify —
ALL PASS (это ловит в т.ч. случайную порчу JSX-логики страниц: verify
сверяет JSON роутов, а битые страницы уронили бы build).

## Что НЕ входит

Публичная часть (лендинг/логин); self-hosted шрифт; новые фичи/поля API;
изменение любых цифр, формул, текстов методологии; остальные ~25 страниц
кабинета за пределами чистки островов (их композиция — по мере надобности
позже).

## Ограничения (наследуются)

Деплой только `npm run build && systemctl restart saas-web`;
`.light/.dark`-механику и имена токенов не менять (только добавка
`--accentInk` и значения warn/pink); тексты по-русски; расхождение цифр =
наш баг.
