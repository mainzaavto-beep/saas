# «Доставлено на склад» — приёмка партий закупки по артикулам

Дата: 2026-10-15. Статус: согласовано с владельцем в диалоге, ждёт ревью спеки.
Часть 1 модуля «Финансы и закупки» (дальше — ДДС, платёжный календарь, баланс; порядок
предварительный, каждая часть — своя спека).

## 1. Зачем

Партия закупки, доставленная на фулфилмент, сейчас кнопкой «✓↧ склад» уходит в
«Остатки склад/ФФ» (`tenant.ff_inventory`) и журнал движений (`stock_moves`, `in`), а оттуда —
в матрицу «Складов», план поставок, авто-списание FBS, «Потребность». На кабинете #1 эта цепочка
не используется: 13 позиций (5 720 шт), ни одна не привязана к месту, документов отгрузки 0 —
матрица и план пусты.

Владельцу нужно другое: видеть, что партия доставлена на ФФ, и после приёмки фулфилментом
зафиксировать, сколько штук принято по каждому артикулу. На этом путь партии заканчивается.

## 2. Решения владельца

1. Страница «Склады» в меню заменяется страницей **«Доставлено на склад»**; вкладки
   матрица / места / поставки из меню убираются (вариант А).
2. На приёмке вводится **принятое количество по каждому артикулу**.
3. «Доставлено на склад» — **конечная точка**: ни остатки склада/ФФ, ни журнал движений, ни
   себестоимость (`cost_overrides`) она не трогает ни до, ни после приёмки.
4. Артикул строки приёмки — **из каталога WB/Ozon кабинета либо вручную** («другое»).

## 3. Поток

```
Закупки (/fin-purchases)
  └─ кнопка «✓ Доставлено» (бывш. «✓↧ склад», action complete_to_stock)
       → purchases.archived = true, delivered_at = delivery_dt || сегодня
       → больше НИЧЕГО (нет INSERT в ff_inventory / ff_inventory_skus, нет applyMove)
Доставлено на склад (/deliveries)
  └─ партия «Ждёт приёмки» → строки «артикул → принято, шт» → галочка «Учтено по артикулам»
       → партия закрыта, строки заморожены. Конец.
```

## 4. Данные (миграция `069_purchase_receipts.sql`, идемпотентная)

`tenant.purchases` — новые колонки:
- `delivered_at date` — дата доставки на ФФ (ставится кнопкой; бэкфилл для уже архивных:
  `COALESCE(delivery_dt, created_at::date)`).
- `receipt_done_at timestamptz` — когда поставлена галочка «Учтено по артикулам» (`NULL` = ждёт).
- `receipt_done_by bigint` — user_id, поставивший галочку.

Новая `tenant.purchase_receipt_lines`:
| колонка | тип | смысл |
|---|---|---|
| `cabinet_id` | bigint | тенант, в PK |
| `id` | bigserial | PK (`cabinet_id, id`) |
| `purchase_id` | bigint | партия, FK `(cabinet_id, purchase_id)` → `tenant.purchases(cabinet_id, id)` |
| `platform` | text | `'wb'` / `'ozon'` / `NULL` (ручной ввод) |
| `nm_id` | bigint | WB-артикул (при `platform='wb'`) |
| `product_id` | bigint | Ozon product_id (при `platform='ozon'`) |
| `label` | text | имя: из каталога (кэш) либо введённое вручную; обязательно |
| `qty_accepted` | integer ≥ 0 | принято, шт |
| `note` | text | примечание (брак, недостача) |
| `created_at`, `updated_at` | timestamptz | |

CHECK: `platform='wb'` ⇒ `nm_id` не NULL; `platform='ozon'` ⇒ `product_id` не NULL;
`platform IS NULL` ⇒ оба NULL. RLS по `app.cabinet_id` + политика `panel_local_ro_cab1`
(как у остальных tenant-таблиц). Маппинг в `lib/db.js` не нужен — роут пишет `tenant.*` явно.
Дубли одного артикула в партии разрешены (разные примечания: «годные» / «брак»).

## 5. Расчёт (чистые функции, `lib/deliveries.js`)

- `receiptTotals(purchase, lines)` → `{ ordered, accepted, diff }`:
  `ordered = round(purchases.qty)`, `accepted = Σ qty_accepted`, `diff = accepted − ordered`.
- `receiptStatus(purchase)` → `'waiting' | 'done'` по `receipt_done_at`.
- `validateLine(line)` → ошибка либо нормализованная строка (целое ≥ 0, label не пуст,
  согласованность platform/артикул).

## 6. API `app/api/cabinets/[id]/deliveries/route.js`

GET (любая роль): `?status=waiting|done|all` (дефолт `all`), `?q=` (поиск по названию партии/строк).
Ответ `{ items: [{ id, name, category, photo, delivered_at, ordered, accepted, diff, status,
receipt_done_at, lines: [...] }], totals: { waiting, done } }`. Источник — `tenant.purchases`
`WHERE archived AND deleted_at IS NULL`, сортировка: ждущие сверху, внутри по `delivered_at` DESC.

POST (`requireRole: 'manager'`), `action`:
- `line_add` `{ purchase_id, platform?, nm_id?, product_id?, label?, qty_accepted, note? }` —
  label для артикула каталога подтягивается из `wb_articles` / `ozon_products`, если не передан.
- `line_update` `{ id, qty_accepted?, note?, label? }`, `line_delete` `{ id }`.
- `done` `{ purchase_id }` — ставит галочку; требует ≥ 1 строки.
- `undone` `{ purchase_id }` — снимает галочку, **только owner** (проверка роли внутри).
- `return_to_purchases` `{ purchase_id }` — вернуть ошибочно отмеченную партию в активные
  закупки (`archived=false`, `delivered_at=NULL`); только если строк приёмки нет.

Правила: любые изменения строк закрытой партии (`receipt_done_at` не NULL) → 400
«партия закрыта, снимите отметку». Партия читается `SELECT … FOR UPDATE` во всех POST.
Порядок проверок — action-блоки до общей проверки id (грабля D10).

GET поиска по каталогу для выбора артикула: `?catalog=1&q=…` → до 20 строк из
`wb_articles` (nm_id, name, im_url) и `ozon_products` (product_id, offer_id, name, im_url).

## 7. Изменения существующего кода

- `app/api/cabinets/[id]/purchases/route.js`, `complete_to_stock`: убрать создание
  `ff_inventory`, `applyMove`, `ff_inventory_skus`; оставить `archived=true` и поставить
  `delivered_at`. Ответ `{ ok: true }`. Имя action не меняем (контракт с фронтом).
- `fin-purchases/PurchasesPage.jsx`: подпись кнопки «✓ Доставлено», текст confirm — «партия
  уйдёт в «Доставлено на склад»», без упоминания «Остатков склад/ФФ».
- `app/cabinets/[id]/layout.js`: в группе «Товары» `{ href: "/warehouses", label: "Склады" }` →
  `{ href: "/deliveries", label: "Доставлено на склад" }`.
- `/warehouses` — роут и страница остаются (на них ссылаются сигналы главной), только не в меню.
- «Остатки склад/ФФ», журнал движений, сигнал «Заканчиваются на складе» — без изменений.
- Последствие (финальное ревью): `/purchase-need` берёт свой склад из `ff_inventory.qty` — новые
  партии туда не попадают, 13 старых позиций (5 720 шт, каб. #1) заморожены; себестоимость новых
  партий — через «Себестоимость» (`/items`). Подача приёмки в потребность — решение владельца.

## 8. UI `app/cabinets/[id]/deliveries/{page.js, DeliveriesPage.jsx, ReceiptPanel.jsx}`

- Шапка: фильтр «Ждут приёмки / Учтено / Все», поиск, счётчики.
- Таблица партий: фото, название, категория, дата доставки, заказано, принято, расхождение
  (красным при ≠ 0), статус-пилл. Клик — раскрытие панели приёмки.
- Панель приёмки: строки (артикул/название, принято, примечание, ✕), «+ артикул» — поиск по
  каталогу WB/Ozon с фото и пункт «другое (ввести вручную)»; итог «принято N из M, расхождение
  ±K»; кнопка «✓ Учтено по артикулам» (подтверждение, если расхождение ≠ 0). У закрытой — строки
  только для чтения, у владельца кнопка «Снять отметку».
- Паттерны проекта: `{ cabinetId }`, fetch в backticks, хуки до ранних return, палитра
  `lib/palette.js` (D1–D7, D13).
