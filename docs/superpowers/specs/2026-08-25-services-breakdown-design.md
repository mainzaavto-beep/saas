# Расшифровка «Сборов Ozon» в карточке товара — дизайн

Дата: 2026-08-25. Статус: согласовано с владельцем (чат) — вариант «тултип на итоге + тултипы дневных ячеек».

## Зачем

Строка «Сборы Ozon» показывает сумму, но не отвечает «за что». Пример владельца: артикул 4191173246 — 5 014 ₽ сборов, из них 4 993 ₽ — три волны «сбора первых отзывов». Расшифровка должна быть видна прямо в карточке.

## Что делаем

Только Ozon-ветка detail (карточка товара). Две точки показа, один источник данных:

1. **Тултип на периодном итоге строки «Сборы Ozon»**: раскладка за выбранный период по типам — «Сбор первых отзывов — 4 993,46 ₽ (3 операции) · Временное размещение — 21,00 ₽ (1)».
2. **Тултип на каждой дневной ячейке строки «Сборы»**: что именно списано «в этот день».

## Данные

- Роут detail (Ozon-ветка) дополнительно отдаёт `servicesBreakdown`:
  - `period`: `[{typeId, label, ops, sum}]` (сортировка по sum desc);
  - `byDay`: `{ 'YYYY-MM-DD': [{typeId, label, sum}] }`.
- Один SQL на период: `tenant.ozon_accruals a JOIN tenant.ozon_order_costs oc ON a.cabinet_id=oc.cabinet_id AND a.unit_number=oc.src_unit_number WHERE oc.product_id = ? AND тип ∈ services-бакет (9 известных + любые позаказные неизвестные — те же правила, что classify_row)`, группировка по `type_id × день`.
- ⚠️ **Датировка — днём отправления** (`substr(COALESCE(oc.sale_dt, oc.return_dt),1,10)`), НЕ днём операции `a.date`: дневная ячейка «Сборы» в ряду считается из order_costs по дню продажи — расшифровка обязана раскладывать ровно ту же сумму. Инвариант: Σ тултипа дня = ячейка дня; Σ period-раскладки = периодный итог `services` (допуск 0,01 ₽ — проверяется приёмочным скриптом, не сторожем).
- Фильтр периода — тот же from/to, что у дневного ряда.
- Словарь подписей `type_id → русское название` — экспорт из lib (единственное место; источники названий — комментарии ozon_profit_map.py); неизвестный тип → «Прочие сборы (тип N)».

## UI

- Существующий hint/title-паттерн DetailPage (как у ConvCard/LocCard) — никаких новых компонентов/цветов; многострочный тултип «label — сумма (ops)».
- Дневные ячейки без сборов — без тултипа. WB-строк не касаемся.

## Не в скоупе

Сводка/P&L (там строка агрегатная по всем товарам — расшифровка отдельной задачей, если понадобится); WB; изменение самих сумм (только отображение).

## Приёмка

- Артикул 4191173246: тултип итога показывает «Сбор первых отзывов 4 993,46 ₽ (3)» + «Временное размещение 21,00 ₽ (1)»; сумма тултипа = строке «Сборы».
- Инвариант Σ тултипов = ячейкам/итогу на 3 товарах с сборами (скрипт-приёмка в отчёте).
- Сторожа ALL PASS (аддитивные поля, числа не меняются).

## Порядок

После волны «окна по вчера» (обе трогают detail — не пересекать ревью).
