## Термины (важно — исправление методологии)

- **Соинвест** — часть скидки, которую доплачивает Озон (не продавец).
- **Акции/буст (`current_boost`)** — скидки и продвижение за счёт ПРОДАВЦА.
  Хозяин подтвердил: буст ≠ соинвест. Старое чтение `current_boost` на РНП
  как «Скидка за счёт МП» — методологическая ошибка (данных всё равно не было:
  `ozon_action_products` пуста, сборщика не существует).

## Источник (проверен живым probe на cabinet #1, 2026-08-02)

`OzonClient.product_info_prices()` (официальный API продавца, прокси не нужен):
- `price.marketing_seller_price` — цена со скидками продавца;
- `price.marketing_price` — итоговая цена с доплатой Озона (null = соинвеста нет);
- также храним `price`, `old_price`, `min_price` (пригодятся, дёшево).

**Соинвест % = 1 − marketing_price / marketing_seller_price**, только если
marketing_price задан и > 0; иначе соинвест = 0 (честный ноль, не пропуск).

## Компоненты

1. **Миграция 030** `tenant.ozon_prices`: PK (cabinet_id, product_id, date);
   поля price, old_price, marketing_seller_price, marketing_price, min_price,
   updated_at. RLS как у остальных tenant-таблиц. Дневной снимок: повторный
   прогон в тот же день перезаписывает сегодняшнюю строку (upsert), история
   по дням копится.
2. **Сборщик** `worker/collectors/ozon_prices.py`: iter_all_products →
   product_info_prices батчами → upsert снимка за сегодня через db_pg
   (`_batch_upsert`, паттерн остальных). Ошибка батча — в лог + счётчик,
   полный провал (0 товаров при непустом каталоге) — exit 1 (FAIL прогона,
   не «OK с нулём» — урок аудита).
3. **Оркестратор**: `ozon_prices` в конец `OZON_COLLECTORS` (едет 4×/день
   и в онбординге).
4. **РНП** (`rnp-summary/route.js`, collectOzon): mpDiscount = средний соинвест
   по снимкам выбранного периода; mpDiscountPrev — по снимкам прошлого периода
   (честная динамика). Блоки boost/boostPrev из `ozon_action_products` удалить.
