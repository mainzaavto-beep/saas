1. **Дельты к прошлому периоду** — в макете под плитками «+7,4 % к прошлому периоду» / «+12,1 %» / «−1,1 п.п.» (pos/neg-цвета); у нас плитки без дельт (SummaryPage Kpi = label+value).

## Решения

### Данные (products-summary route)

- **prevTotals**: те же агрегаты за предыдущее окно той же длины, СТЫКОМ к текущему (prev_to = from−1, prev_from = prev_to−(N−1)); считаются тем же batch-каноном (+2 SQL на прогон). Отдаются рядом с totals; дельты считает клиент. Для явных периодов — так же (прошлое окно той же длины).
- **profitSpark**: дневной ряд прибыли кабинета за текущее окно для спарклайна — Σ по дням из order_costs обеих площадок (WB+Ozon дневные канон-агрегаты уже есть: wbRawProfitByDay/ozRawProfitByDay — но они per-товар; для кабинета — GROUP BY день без product-фильтра тем же SELECT'ом: новый лёгкий хелпер `*RawProfitCabinetByDay` ИЛИ переиспользовать серию Обзора, если она уже канонична — решить при планировании разведкой, НЕ дублировать формулу). Спарклайн — сырой rawProfit по дням достаточен (реклама/налог по дням кабинета уже посчитаны нигде? если дорого — спарклайн по rawProfit с подписью, честность подписи обязательна) — уточнение: считать полный profit дня кабинета = Σ ozDayProfit/wbDayProfit по товарам дорого; РЕШЕНИЕ: спарклайн по «прибыль дня = rawProfit − реклама дня» (реклама дня кабинета из daily_metrics Σ — дёшево), налог опустить с подписью в тултипе плитки «до налога»; либо если Обзор уже отдаёт дневную прибыль — взять её один в один. Выбор зафиксировать в плане после разведки, формулу не изобретать.
- **Дельта Выкупа** — в п.п. (не %), как в макете.

### ДРР-пиллы (клиент)

Правило (решение владельца): относительно маржи товара за период —
- зелёный (ok): drr < margin/2;
- жёлтый (warn): margin/2 ≤ drr < margin;
- красный (bad): drr ≥ margin ИЛИ (реклама > 0 и продаж 0 — пилл «—»).
- Без рекламы — пилла нет, прочерк как сейчас. margin ≤ 0 при drr > 0 — красный.
Стиль пилла — как макет: font 11.5/600, radius 6, padding 2/8, цвет pos/warn/neg, подложка soft(...,12-14) — существующие токены.

### KPI-ряд

Как макет: 5 плиток — Прибыль (primary, спарклайн справа, дельта), Выручка (Δ%), Реклама (подпись «ДРР N %» muted — общекабинетный ДРР, как текущая плитка «ДРР (общий)»), Продано шт (Δ%), Выкуп (Δ п.п.). Убираемые плитки (Маржа, Заказано, CPA и пр.) — метрики остаются в таблице; плитки удаляются (макет чище). Grid 1.6fr+1fr×4, как макет.

### Прочее из макета

Двухэтажная ячейка товара (имя жирным + «Площадка · артикул» серым 12px) и категория-чип — сверить с текущей реализацией, привести к макету, если отличается. Топбар/фильтры-чипы — уже есть (рестайл 1-3), не трогать.

## Не в скоупе

Другие страницы; изменение формул метрик (только отображение + prevTotals/spark аддитивно); тёмная тема — через существующие токены автоматически.

## Приёмка

- Плитки показывают дельты (сверка вручную с двумя явными окнами через query-параметры); спарклайн монотонно соответствует дневным данным (сверка 3 точек с SQL).
- ДРР-пиллы: проверить на товарах из макета-логики (высокая маржа + высокий ДРР = зелёный; ниже маржи = жёлтый; выше = красный; реклама без продаж = красный «—»).
- Сторожа ALL PASS (аддитивные поля).
