# Процент выкупа: корзина по покупателю Ozon и перезаказы (20.10.2026)

Продолжение `2026-10-20-buyout-fitting-design.md` (разрез «Одиночные / Примерки»). Решения владельца —
20.10.2026.

## Проба (каб. #1, только чтение, 20.10.2026)

Первая часть номера отправления Ozon (`0119456225-0516-1` → `0119456225`) ведёт себя как аккаунт
покупателя: вторая часть внутри префикса растёт строго по дате (1153/1153 пар), счётчики до 1–1,6 тыс.
(заказы человека на всём Ozon); у 286 из 301 префикса с 2+ заказами все заказы в один регион (95 %,
у случайной пары — 2,3 %). Аномалия — 3 префикса `0267473…` (31.07–01.08: 7–21 заказ за день в 3–6
регионов, все отменены) — не покупатели. У нормальных за день ≤ 5 заказов и ≤ 2 регионов. Это
НАБЛЮДЕНИЕ, не документированное поле Ozon. У WB ID покупателя нет — только корзина `g_number`.

FBO, 90 дн: примерок внутри заказа 85; пар «тот же покупатель и модель, другой вариант, другой заказ,
≤ 7 дн» — 110 (51 в тот же день, 59 через 1–7 дн: «баклаж-L отменён → назавтра баклаж-XL»).

## Решения

1. **Корзина Ozon = покупатель + день заказа** (было — номер заказа). Покупатель = первая часть
   `posting_number`. **Аномальный покупатель** — хоть в один день загруженного окна заказы в 3+
   регионах (`ANOMALY_REGIONS_PER_DAY = 3`): его корзина остаётся номером заказа, в перезаказах он не
   участвует. WB — без изменений.
2. **Перезаказ.** Заказ A «не выкуплен покупателем»: ведро `refused` или `returned`, либо статус
   `cancelled` с причиной НЕ из `OZ_OZONSIDE_REASON_PREFIXES` (отмена покупателем, в т.ч. без
   причины). Перезаказ — первый заказ B того же покупателя и той же модели с ДРУГИМ вариантом, дата B
   строго позже даты A и не позже A + 7 дн (`REORDER_WINDOW_DAYS = 7`; тот же день — уже корзина).
   Самовыкупы не участвуют. Цепочки A→B→C размечаются звеньями.
3. **Тип строки** `fit_reorder` («Перезаказ»): получают A и B, если они не примерка по корзине
   (корзина главнее). Фильтр `&fit=reorder`; `fitting` включает `fit_reorder` — «Одиночные» = один
   вариант модели на покупателя в пределах недели (решение владельца: вариант 1). Инвариант
   `single + fitting = all` сохраняется; `size + color + mixed + reorder = fitting`.
4. **`fittingSummary`** остаётся сводкой примерок ПО КОРЗИНЕ: строки `fit_reorder` в ней не считаются
   ни примерочными корзинами, ни примерочными строками.
5. **Края периода.** Роут грузит строки с запасом ±7 дн (`[from − 7, min(to + 7, asOf)]`), размечает
   корзины и перезаказы по всем загруженным строкам, затем оставляет в когорте только `from..to`.
   Категории, KPI, таблица, график — только по строкам периода. B может лежать за `to` — его судьба
   берётся из загруженных строк.
6. **`reorderSummary(periodRows, allRows, asOf)`** (только Ozon, не аномальные покупатели):
   `dropped` — невыкупленных заказов в периоде; `pairs` — из них с перезаказом; `reorderShare`;
   `bBuyoutPct` — доля выкупленных B среди решённых (sold/refused/returned); по моделям — `pairs`,
   направление `sizeUp` / `sizeDown` (размер изменился, цвет тот же; порядок — `sortSizes`), `color`
   (цвет изменился или варианты различимы только по id), `mixed` (и цвет, и размер), `bBuyoutPct`,
   комбинации по артикулам (`коричн-цвет-L → коричн-цвет-XL`).

## API и UI

- Ответ периода дополняется `reorders` (результат `reorderSummary` по строкам периода после фильтра
  категорий, до фильтра `fit`). `FIT_VALUES` += `reorder`. `series=1` — то же расширенное окно.
- `/buyout`: в переключатель — «Перезаказы»; в подписи плитки «Примерки» — число перезаказов;
  сворачиваемый блок «Перезаказы (Ozon)»: строка «после N % невыкупленных заказов Ozon покупатель в
  течение 7 дней заказал другой вариант; второй выкупают в M %», таблица по моделям. Оговорка:
  покупатель определяется по номеру заказа Ozon (наблюдение, не официальное поле); у WB не видно.
