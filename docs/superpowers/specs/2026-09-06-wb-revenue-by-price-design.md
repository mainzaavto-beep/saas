# Выручка WB по цене со скидкой продавца — переезд канона

Дата: 2026-09-06. Статус: утверждена владельцем («делай 1 и 2 везде»).

## Причина

Владелец на «Сводке по товарам» (фильтр WB) увидел «Баклажан-цвет: продано 11 шт на 12 696 ₽»
и «Видеорегистратор дешёвый ребристый: заказано 5 шт на 3 445 ₽». Разбор 06.09:

| Симптом | Причина | Класс |
|---|---|---|
| «Заказано 5» при одном заказе в периоде | `products-summary/route.js:630`: `ordered = max(ordered, sold + cancelled)` — инвариант «заказано ≥ продано» верен за всё время, но не внутри окна (продажи сентября по заказам августа) | баг |
| «Продано 11» при «12 696 ₽» | штуки — из ленты продаж (свежая), рубли — из `wb_order_costs` (отстаёт на сутки, 9 строк) | два источника в одной строке |
| 12 696 ₽ ≈ 1 410 ₽/шт при цене 2 835 ₽ | канон с 20.08: `revenue = cost_value_pay` («к перечислению» WB) и маржа от него | методология, владельцу не подходит |

Решение владельца: **выручка WB = сумма продаж по цене со скидкой продавца**, **маржа = прибыль ÷ эта выручка**, везде.

## Что вскрыли данные (кабинет 1, отчёт реализации WB)

| Факт | Следствие |
|---|---|
| В `wb_finance_report` три цены: `retail_price_withdisc_rub` (цена со скидкой продавца, = `price_with_disc` ленты продаж), `retail_amount` («реализовано», покупатель заплатил после СПП), `ppvz_for_pay` («к перечислению») | Выручка = `retail_price_withdisc_rub`; СПП = withdisc − realized; вознаграждение WB нетто = realized − payout |
| Компонентное разложение `retail_amount − комиссия − эквайринг = ppvz_for_pay` **не сходится** ни на одной из 478 строк июля (комиссия часто отрицательная — WB компенсирует СПП внутри `ppvz_vw`); суммарно за июль: realized 872 568, комиссия 83 169, эквайринг 32 708, payout 851 969 | Единственная честная строка расходов площадки — нетто `realized − payout` (июль: 20 599 ₽, 2,4 %). Отчётные `commission/acquiring/loyalty` остаются справочными |
| Ozon: `revenue = Σ cost_value_retail` уже валовая, комиссия вычитается отдельно | Меняется только WB; формы ответа канона общие |
| `wb_finance_report`/`wb_order_costs` есть только у кабинета 1 | Бэкфилл новой колонки — только кабинет 1 |
| Налог кабинета 1 — УСН «Доходы» 6 % | База сейчас = payout. Доход продавца по отчёту WB — «реализовано» (`retail_amount`): столько заплатил покупатель, столько агент получил за товар продавца |

## Модель (WB)

Новая колонка `tenant.wb_order_costs.cost_value_withdisc` = Σ `retail_price_withdisc_rub` строк «Продажа» по `srid`, обнуляется при `is_return=1` так же, как `cost_value_retail`/`cost_value_pay` (возврат = убыток на логистику, выручка 0).

Агрегат канона (`wbRawProfitAggregate` и три его формы) отдаёт:

| Поле | Формула | Смысл |
|---|---|---|
| `revenue` | Σ `cost_value_withdisc` | продажи по цене со скидкой продавца |
| `realized` | Σ `cost_value_retail` | реализовано (заплатил покупатель) |
| `payout` | Σ `cost_value_pay` | к перечислению |
| `spp` | `revenue − realized` | скидка WB (СПП) |
| `commission` | `realized − payout` | вознаграждение WB нетто (комиссия + эквайринг − компенсации); **это вычет** |
| `commissionReport`, `acquiringReport`, `loyaltyReport` | Σ отчётных колонок | справочно, не вычитаются |
| `acquiring`, `loyalty` | 0 | форма общая с Ozon; у WB внутри `commission` |
| `cogs`, `logistics`, `rawProfit`, `returnLogistics` | без изменений | |

Тождества (сторож): `revenue − spp − commission = payout`; `profitGross = revenue − spp − commission − cogs − logistics = rawProfit`.

Прибыль: `profit = rawProfit − ads − tax` — структура не меняется; **рубли прибыли меняются только на разницу налога**.

Налог: база `WB_TAX_BASE = "realized"` (одна константа в `lib/wbMetrics.js`, переключаема на `"revenue"` или `"payout"`); расходы для УСН Д−Р = `cogs + logistics + ads + commission`. Ozon без изменений.

Маржа: `profit / revenue × 100` на всех страницах (одна формула, база теперь валовая у обеих площадок).

Ozon для симметрии формы: `spp = 0`, `realized = revenue`, `payout = revenue − commission − services − acquiring − loyalty`, `*Report` отсутствуют.

## Сторожа

- `scripts/check-profit-canon.mjs` (WB): независимый SQL `revenue = Σ cost_value_withdisc`; тождества выше; `Σ profit(товар)` = `profit(кабинет)` с тем же допуском, что сейчас.
- Снимок «до» (`scratchpad/wb-canon-baseline-2026-09-06.txt`, помесячно `pay/realized/cogs/logistics/rawProfit`): после переезда `profit_new − profit_old = −(tax_new − tax_old)` для каждого месяца, `rawProfit` бит-в-бит.
- Бэкфилл: по каждому `srid` с `is_return=0` `cost_value_withdisc` = Σ `retail_price_withdisc_rub` строк «Продажа» (Δ = 0).
- Приёмка владельцем на кабинете 1, период 01–05.09: «Баклажан-цвет» продано 9 на 25 515 ₽ (9 × цена со скидкой), «Видеорегистратор дешёвый ребристый» заказано 1 на 3 445 ₽, продано 5.

## Вне рамок

- Ozon-методология и юнит-экономика (`lib/unit.js`) не трогаются.
- Разложение вознаграждения WB на комиссию/эквайринг/компенсации СПП — только справочные поля; в P&L одна нетто-строка.
- Подтверждение налоговой базы у бухгалтера — решение владельца; переключение одной константой.
