# Юнитка: галочки «с браком»/«с % выкупа» и ставка УСН — дизайн

Дата: 2026-08-27. Статус: согласовано с владельцем: обе площадки; ставка УСН — одна сверху для всех строк; сборы в юнит-модель НЕ добавляем (решение 27.08).

## Контекст

Модель уже умеет больше, чем показывает: `usnRate` заложен в calcWB (lib/unit.js:127, дефолт TAX.USN_RATE), брак/выкуп есть у WB (defectRate/profitWithDefect/buyout); Ozon-модель имеет buyout, но не имеет брака. Владелец хочет управлять режимами явно.

## Решения

1. **Две галочки сверху** (рядом с «все колонки», тот же label-паттерн): «с % выкупа», «с браком». Состояние — localStorage (view-настройка, не данные).
   - «с % выкупа» ON: показываются поля выкупа и расчёт учитывает выкуп (как сейчас у WB: логистика делится на выкуп и т.п.); OFF: поля скрыты, в calc подаётся buyout=1 (100%) — расчёт «как будто выкупается всё».
   - «с браком» ON: поля «% брака» и «прибыль/маржа с браком» видимы и считаются; OFF: скрыты, defectRate=0 в calc.
   - Галочки управляют И колонками, И расчётным режимом — «считать и так и так» по клику.
2. **Ozon-модель дорастает до WB**: defectRate/defectLoss/profitWithDefect зеркалом WB-подхода (defectLoss = закупка × брак; выкуп у Ozon уже есть — сверить применение по месту, буквально повторить семантику WB там, где Ozon её не имеет). Формулы прибыли БЕЗ галочек не меняются (галочки OFF = текущее поведение, регресс-инвариант).
3. **Ставка УСН**: поле «Ставка УСН, %» сверху (у галочек), одно на площадку-вкладку; дефолт = фактическая ставка кабинета (тот же источник, что канон-налог — не хардкод 6%); введённое значение уходит в calc как usnRate ВСЕХ строк прикидки; персист — в tenant.unit_whatif сентинель-записью item_id=0 (inputs {usnRate}), сервер расширяет whitelist для item_id=0 отдельным набором {usnRate: max 0.25}; сид при загрузке; сброс поля к дефолту удаляет сентинель.
4. Строковая прикидка приоритетнее глобальной ставки нигде не бывает (ставка одна — в строках поля УСН-ставки нет).

## Не в скоупе

Сборы/шт (решение владельца — не нужны); изменение формул при выключенных галочках; WB-вкладка колонок за пределами перечисленного.

## Приёмка

- Галочки переключают колонки и расчёт на обеих вкладках; OFF+OFF = прежние числа (регресс-инвариант на 2-3 товарах, до/после — совпадение).
- Ставка: изменение поля пересчитывает УСН/прибыль всех строк; F5 — ставка на месте (сентинель в БД, SQL-подтверждение); сброс — дефолт кабинета, сентинель удалён.
- Ozon: брак считается зеркально WB (ручная сверка формулы на одном товаре: defectLoss = закупка×брак, прибыль с браком = прибыль − defectLoss).
- Сторожа ALL PASS.

## Порядок

Конвейер SDD: (1) lib-модель Ozon + сервер (whitelist/sentinel), (2) UI галочки+ставка+деплой, (3) контракт-строка + финал.
