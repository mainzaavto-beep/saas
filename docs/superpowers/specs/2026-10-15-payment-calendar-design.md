# Платёжный календарь и план поступлений — дизайн

Дата: 2026-10-15. Часть 2 модуля «Финансы и закупки» (часть 1 — «Доставлено на склад»).
Образец владельца — скрин «Платёжный календарь» стороннего сервиса (месячная сетка платежей).

## 1. Цель и рамки

Владелец видит по дням, кому и сколько платить (расходы) и когда придут деньги (поступления), отмечает
оплату одним кликом. Всё — поверх одной таблицы денег `tenant.dds_movements`, чтобы ДДС, календарь и план
поступлений были тремя видами одних данных и не могли разойтись.

Входит:
- миграция 070 (поля источника в `dds_movements`, шаблоны повторов `dds_recurring`);
- автоплатежи из «Закупок» (до 4 на партию);
- повторяющиеся платежи (шаблоны);
- прогноз выплат WB/Ozon как плановые поступления;
- страницы «Платёжный календарь» и «План поступлений», вкладки `ДДС | План поступлений | Платёжный календарь`.

Не входит (отдельные проекты): перестройка навигации всей панели (разделы сверху, подразделы слева);
переделка страницы ДДС; бюджет и план-факт; прогноз поступлений по плану продаж; банковская интеграция.

## 2. Данные (миграция `070_payment_calendar.sql`, идемпотентна)

### 2.1 `tenant.dds_movements` — новые колонки

| Колонка | Тип | Смысл |
|---|---|---|
| `source_kind` | text NOT NULL DEFAULT 'manual' | `manual` \| `recurring` \| `purchase` \| `mp_payout` |
| `source_ref` | text NULL | ключ источника (см. ниже); NULL у `manual` |
| `amount_planned` | numeric NULL | сколько ждали; `amount` — по факту после отметки |
| `paid_at` | timestamptz NULL | когда отмечено «оплачено/получено» |
| `date_locked` | boolean NOT NULL DEFAULT false | дату сдвинули руками — источник её больше не перезаписывает |

- Частичный уникальный индекс `(cabinet_id, source_kind, source_ref) WHERE source_ref IS NOT NULL
  AND status <> 'archived'` — повторная генерация не плодит дубли.
- `source_ref`: `recurring:<template_id>:<YYYY-MM-DD>`; `purchase:<id>:prepay|balance|cargo|ff`;
  `wb:<YYYY-MM-DD понедельника недели>`; `ozon:<YYYY-MM>-1` (1–15) / `ozon:<YYYY-MM>-2` (16–конец).
- Статусы: `planned` → `paid`; `archived` = удалено (как сейчас). Существующие строки: `source_kind='manual'`.

### 2.2 `tenant.dds_recurring` — шаблоны повторов

`cabinet_id, id, type (income|expense), amount, category, counterparty, description,
rule (monthly|weekly|every_n_days), rule_day (число месяца 1..31 / день недели 1..7), every_n,
date_from, date_to NULL, is_active, created_at, updated_at`. RLS как у прочих `tenant.*`,
политика `panel_local_ro_cab1`, маппинг в `lib/db.js`.

- Раскладка: строки `planned` на горизонт 3 месяца вперёд от сегодня; генерация при открытии календаря
  (лениво, идемпотентно по `source_ref`) и при сохранении шаблона.
- `monthly` с `rule_day` больше длины месяца → последний день месяца.
- Правка шаблона меняет только будущие неоплаченные строки без `date_locked`; оплаченные и прошедшие не трогает.
  Удаление/выключение шаблона архивирует будущие неоплаченные строки.

### 2.3 Платежи из «Закупок»

Чистая функция `purchasePayments(purchase)` по формулам `computeExcel` (`purchases/route.js`):

| Ключ | Статья | Сумма | Дата (иначе плановая) |
|---|---|---|---|
| `prepay` | Поставщик — предоплата | `N = L×M` | `order_dt` ← `plan_order_dt` |
| `balance` | Поставщик — остаток | `W − N` (= `R×U`) | `ship_dt` ← `plan_ship_dt` |
| `cargo` | Карго до МСК | `X×O` | `delivery_dt` ← `plan_arrival_dt` |
| `ff` | Логистика МСК→ФФ | `Y×O` | `delivery_dt` ← `plan_arrival_dt` |

- Σ четырёх = `Z` партии (инвариант, тест + смоук). Нулевые суммы не создаются; нет ни одной даты → берётся
  `date` партии.
- Остаток поставщику — `W − N` (= `R×U`, по курсу оплаты `U`), а НЕ `S = M×R` (курс аванса): иначе сумма
  платежей ≠ себестоимости партии. Решение владельца 15.10: «остаток к оплате» везде по курсу оплаты —
  `calc_balance_due` в `purchases/route.js` тоже переводится с `S` на `R×U` (колонка `S` в таблице остаётся
  как формула Excel владельца).
- Контрагент — `supplier_name`; описание — `«Партия #id · <товар>»`.
- Синхронизация — в той же транзакции, что сохранение партии (`create`/`update`/удаление в
  `purchases/route.js`): upsert по `source_ref`; у строк `paid` ничего не меняется; у `planned` обновляются
  сумма и (если не `date_locked`) дата; ключ, ставший нулевым, архивируется, если не оплачен. Удаление партии →
  архив неоплаченных. Ошибка синхронизации = ошибка сохранения партии (никаких пустых `catch`).
- `pay_status='paid'` у партии на платежи не влияет (это старое общее поле; оплата — по строкам календаря).
- Бэкфилл: разовый прогон синхронизации по всем неудалённым партиям кабинета #1 (скрипт, на #1).

### 2.4 Прогноз выплат маркетплейсов

Не хранится заранее: в календаре на каждое окно выплаты строка-прогноз считается на лету.

- **WB:** окно — неделя Пн–Вс по `rr_dt`; сумма = «итого к оплате» = `payout` (`ppvz_for_pay`, контракт §1.1)
  − логистика − хранение − штрафы − удержания − платная приёмка (те же строки, что кабинетные расходы
  `wbProfitCabinet`, включая «WB Продвижение» — деньги удерживаются реально, хоть в прибыли и не вычитаются
  второй раз). Это НОВАЯ величина `cashPayout` — вносится в `docs/metrics-contract.md` отдельным пунктом;
  дата — день выплаты следующей недели (дефолт: среда).
- **Ozon:** окна 1–15 и 16–конец месяца; сумма = Σ начислений `ozon_accruals.accrued` за окно; даты —
  20-е текущего (за 1–15) и 5-е следующего (за 16–конец) месяца.
- Формулы — новые функции в `lib/wbMetrics.js` (`wbPayoutByWindow`) и `lib/ozonMetrics.js`
  (`ozPayoutByWindow`), не инлайн в роуте. Дни выплат — `auth.cabinets.settings.payouts`
  (`{wb:{weekday:3}, ozon:{day1:20, day2:5}}`), поле в «⚙️ Настройках». Дефолты подтверждены владельцем 15.10.
- Незавершённое окно (текущая неделя/полумесяц) показывается с пометкой «копится», сумма — по уже
  собранным дням.
- «Получено» → строка записывается в `dds_movements` (`source_kind='mp_payout'`, `status='paid'`,
  `amount_planned` = прогноз, `amount` = введённый факт) и дальше не пересчитывается. Снятие отметки —
  строка архивируется, снова виден прогноз.
- Если в окне нет данных площадки (магазин не подключён) — строки нет.

## 3. Экраны

### 3.1 Вкладки и меню
Общий компонент `FinanceMoneyTabs` (ссылки): `ДДС | План поступлений | Платёжный календарь` — сверху на трёх
страницах. Меню «Финансы»: «План платежей» → «Платёжный календарь» (`/fin-calendar`), новый пункт
«План поступлений» (`/fin-income`). Старая недельная страница `/fin-calendar`, `payment-plan` API и
`lib/calendarCalc.js` удаляются (источники пустые; бэкап в `/opt/agentsDB/backups/`).

### 3.2 Платёжный календарь (`kind=expense`)
- Шапка: ← месяц → «Сегодня», «+ Платёж». Итоги месяца: запланировано / оплачено / осталось / просрочено.
- Сетка Пн–Вс, 5–6 недель (дни соседних месяцев — бледные). Ячейка: число (сегодня — кружок акцента), до 3
  платежей «статья · контрагент — сумма», «ещё N» (клик — список дня), внизу сумма дня.
- Платёж: кружок → клик «оплачено» (зелёная галочка, текст зачёркнут, `paid_at`); повторный клик снимает.
  Просроченный (дата < сегодня, не оплачен) — красная рамка.
- Цвет — по статье: Поставщик, Карго/логистика, Фулфилмент, Налоги, Зарплата, Аренда, Подписки, Реклама,
  Прочее (старые категории ДДС «Закупка»/«ЗП» маппятся на «Поставщик»/«Зарплата»). Палитра — `lib/palette.js`.
- Колонка «Итого» недели: сумма, подпись «всё оплачено» либо «осталось N».

### 3.3 План поступлений (`kind=income`)
Та же сетка (общий компонент `MoneyCalendar`). Прогнозы МП — значок площадки, подпись «ожидается»/«копится»;
«получено» открывает поле фактической суммы (по умолчанию = прогноз). Ручные поступления и повторы — как у расходов.

### 3.4 Карточка платежа (модалка)
Дата, сумма, статья, контрагент, комментарий, «Повторять…» (ежемесячно N-го / еженедельно / каждые N дней,
до даты) — создаёт шаблон. Платёж из Закупок: ссылка на партию, сумма только для чтения, дату менять можно
(→ `date_locked`). Повторяющийся: «изменить только этот» / «изменить шаблон». Удалить — архив.

### 3.5 Роли
GET — все роли кабинета; запись — `requireRole: 'manager'` (как ДДС). Viewer кнопок правки не видит.

## 6. Риски

- Изменение сохранения партии (`purchases/route.js`) — ошибка синхронизации блокирует сохранение партии;
  это намеренно (иначе тихий рассинхрон), покрыто тестами.
- Прогноз выплат — оценка: реальная выплата может отличаться (удержания, досписания). Отметка «получено»
  с фактической суммой — источник правды.
