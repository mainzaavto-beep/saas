# Юнитка: режимы брак/выкуп и ставка УСН — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Две галочки сверху («с % выкупа», «с браком») переключают колонки и расчёт на обеих вкладках; глобальное поле «Ставка УСН, %» пересчитывает все прикидки и переживает F5.

**Architecture:** Ozon-модель дорастает до WB (defect-зеркало); галочки OFF подают в calc нейтральные входы (buyout=1, defectRate=0) — прежние числа как регресс-инвариант; ставка УСН — сентинель item_id=0 в tenant.unit_whatif с отдельным whitelist.

**Tech Stack:** Node/ESM (lib/unit.js, unit-роуты), React (UnitPage).

**Спека:** `docs/superpowers/specs/2026-08-27-unit-modes-design.md`.

## Global Constraints

- Регресс-инвариант: при галочках OFF+OFF и дефолтной ставке числа строк БАЙТ-В-БАЙТ прежние (проверка на 2-3 товарах обеих платформ до/после — в приёмке каждой задачи, где менялся calc-путь).
- Формулы WB не меняются; Ozon получает ТОЛЬКО зеркальные defect-поля (семантика 1:1 с WB: defectLoss = закупка × defectRate; profitWithDefect = profit − defectLoss; marginWithDefect аналогично WB).
- Ставка УСН: дефолт = фактическая ставка кабинета из того же источника, что канон-налог (найти, как unit/all получает налоговые параметры; НЕ хардкод 6%); сентинель item_id=0, whitelist {usnRate: min 0, max 0.25}, inputs:null → удаление сентинеля.
- git add — только явный список файлов. Тексты по-русски. Токены/паттерны существующие.
- Сторожа после каждой задачи: check-profit-canon --cabinet 1, --cabinet 1008, profit-snapshot --verify — ALL PASS дословно.
- Деплой только в задаче 2.
