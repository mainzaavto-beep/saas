# Дефолтные окна «по вчера» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Дефолтные финансовые окна панели заканчиваются вчера (сегодня недособрано и занижает прибыль); ручной выбор периода не ограничивается; окна «от последних данных» (MAX(order_dt)) и операционные даты не трогаются.

**Architecture:** Один хелпер `lib/period.js` (`defaultPeriod(days)` → 30 дней по вчера, UTC-строки как всюду) + перевод дефолтов по правилу классификации; клиентские якоря сверяются с `period.from/to` ответа.

**Tech Stack:** Node/ESM (lib, роуты), React (якоря пикеров).

**Спека:** `docs/superpowers/specs/2026-08-25-default-period-yesterday-design.md` (d735c69).

## Global Constraints

- Правило классификации места (применять к КАЖДОМУ найденному `new Date().toISOString().slice(0,10)`-дефолту):
  (а) дефолт финансового ОКНА «по сегодня» → `defaultPeriod(N)` (по вчера, длина сохраняется);
  (б) дефолт «от MAX(order_dt)» → НЕ трогать (но его fallback-ветку «нет данных → по сегодня» → тоже `defaultPeriod(N)` для консистентности);
  (в) операционная дата (ship_dt/delivery_dt fallback, «баланс на дату», live-показатели «на сейчас») → НЕ трогать;
  (г) неочевидное (расчёт elapsed-дней, границы месяца plan/fact) → НЕ менять без явного разбора; решение с обоснованием — в отчёт.
- Явно переданные query-параметры периода нигде не ограничиваются.
- Сторожа после каждой задачи: `node scripts/check-profit-canon.mjs --cabinet 1`, `--cabinet 1008`, `node scripts/profit-snapshot.mjs --verify` — ALL PASS (их окна фиксированные/явные — не должны шевельнуться).
- Деплой только в задаче 3. Тексты по-русски. В отчётах — дословный вывод команд.

- [ ] **Step 1:** `lib/period.js` целиком:

```js
// Дефолтное окно панели: последние N дней ПО ВЧЕРА. Сегодняшний день
// финансово всегда недособран (логистика/реклама/сборы начисляются раньше
// выручки) — текущая дата в дефолте занижает прибыль (решение владельца
// 2026-08-25). Ручной выбор периода этим НЕ ограничивается.
// Датировка — UTC-строками, как во всех роутах (договорённость не меняем).
export function defaultPeriod(days = 30) {
  const to = new Date(Date.now() - 864e5).toISOString().slice(0, 10);
  const from = new Date(Date.now() - days * 864e5).toISOString().slice(0, 10);
  return { from, to };
}
```

```js

  const from = fromQ || def.from;
```

(импорт `defaultPeriod` из `@/lib/period.js`; окно lossMakers/kpi/графиков едет за from/to автоматически — отдельных дефолтов в роуте нет, проверить grep-ом по файлу).
