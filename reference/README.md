# Эталонные данные

## Зачем нужен эталон

Эталон — это официальные цифры из личных кабинетов маркетплейсов (Wildberries и Ozon).
Он служит для проверки правильности наших расчётов в панели аналитики: мы сверяем
то, что панель показывает, с тем, что говорит сам маркетплейс.

Эталон намеренно **строгий**: незаполненная величина считается ошибкой, а не нулём.
Молчаливый ноль превратил бы сверку в вечнозелёную — бесполезную для ловли багов.

## Как заполнить эталон

1. **Откройте личные кабинеты** обеих платформ — только у владельца сервиса есть доступ.

2. **Для Wildberries:**
   - Перейдите в **Финансы → Отчёт о реализации** (еженедельный).
   - Выгрузите все недели за период.
   - Скопируйте границы дат из самого отчёта (не из календаря).
   - Заполните `expected.json`: укажите `date_from`, `date_to` и `report_id`.
   - Распишите сумму по строкам: продажи, возвраты, комиссия, логистика, хранение, штрафы, удержания, к выплате, расходы на рекламу.
   - Сохраните скриншот или CSV отчёта рядом с `expected.json`.

3. **Для Ozon:**
   - Перейдите в **Финансы → Начисления**.
   - Выберите месяц.
   - Выгрузите отчёт.
   - Заполните в `expected.json`: `date_from`, `date_to`, `report_id`.
   - Распишите суммы: продажи, возвраты, комиссия, логистика, выплата, расходы на рекламу.
   - Сохраните скриншот или выгрузку.

4. **Обновите таблицу в `SOURCES.md`** — добавьте строку с номером отчёта, периодом, датой выгрузки и именем того, кто выгружал.

## Правило изменения

**Числа в `expected.json` меняются только, если маркетплейс пересчитал отчёт.**
Если это произошло:
- Выгрузите актуальный отчёт повторно.
- Обновите значения в `expected.json`.
- Добавьте новую строку в таблицу `SOURCES.md` с пометкой — почему изменилось.

**Запрещено подгонять эталон под то, что показывает панель.** Эталон существует именно
для того, чтобы ловить наши расхождения. Если панель не совпадает с маркетплейсом —
виноват код, а не эталон.

## Структура каталога

```
reference/
├── README.md                          (этот файл)
└── 2026-07-cabinet-1/
    ├── expected.json                  (структура и значения)
    ├── SOURCES.md                     (откуда взялись числа)
    ├── wildberries-week-1.csv         (выгрузка для каждой недели)
    ├── wildberries-week-2.csv
    ├── ozon-july-2026.csv             (выгрузка месячная)
    └── …
```

## Что делать, если маркетплейс пересчитал отчёт

1. Заметьте дату и причину в `SOURCES.md`.
2. Выгрузите актуальный отчёт.
3. Обновите значения в `expected.json`.
4. Панель упадёт на сверке — это нормально, значит, наш расчёт не совпадал с новыми цифрами маркетплейса.
5. Найдите и чините баг в панели.
